## P1：仍存在用户配置被覆盖的情况

源码位置：`src/dlss_combo/install.py:187`、`src/dlss_combo/uninstall.py:30`。v0.1.0 与当前 HEAD 的产品源码相同；后续差异仅为复现脚本的 UTF-8 读写修正。

临时目录复现步骤：

1. 安装前放置用户自己的 `dlssg_sm86.ini`。
2. 安装成功后，再手工修改这个 INI。
3. 分别执行重装、卸载。

两种情况下，用户的安装后修改都未保留：

- 重装识别为外部修改并打印保留警告，但随后无条件写入生成的 INI。
- 卸载先按哈希跳过外部修改文件，随后又无条件把首次安装前备份覆盖到同一路径。

建议：外部修改的 INI 应直接保留；恢复备份时遇到已存在的外部修改目标，应中止覆盖或另存恢复副本。增加“安装前原配置→安装→用户修改→重装/卸载”的独立回归测试。不要仅凭原九个用例通过，宣称所有文件保护问题已解决。

## P2：Linux 包有明确的系统运行库下限

构建 runner 是 Ubuntu 24.04，内嵌 Python 3.13。静态解析 PyInstaller 归档及 `libpython3.13.so.1.0` 的 ELF 版本依赖表，确认它要求系统 `libc.so.6` 和 `libm.so.6` 提供 `GLIBC_2.38`。

因此该包至少要求 glibc 2.38；这是必要条件，不代表满足此版本就已经完成所有发行版兼容性验收。仅检查外层启动器会漏掉这个要求：外层最高版本标记只有 GLIBC_2.14。

建议发布页明确写 `Linux x86-64, glibc >= 2.38, experimental`；若要扩大覆盖，在声明支持的较旧构建环境中打包，再在多个目标发行版验证启动和完整 CLI 流程。[PyInstaller 官方兼容性说明](https://pyinstaller.org/en/stable/usage.html#making-gnu-linux-apps-forward-compatible)

## P2：有 Linux 工具不等于组合方案通过 Proton 实测

Linux 文件是原生命令行编排器，上游代理仍然是 Windows DLL。发布说明把游戏目录限定在 Proton prefix 内过于绝对；用户应该选择 Steam“浏览本地文件”得到的实际游戏目录，并定位渲染 EXE，不应把 Wine prefix 当成所有游戏文件的固定所在位置。

应分别标明：CLI 能启动、能摆放文件、Wine 加载代理、DLSS-G 后端激活、画质层生效。这些是不同的验收层级。当前没有后几项的本项目实测证据。

NVAPI/CUDA 环境变量应标明所针对的 Proton 版本，不应根据另一个 mod 的指引推导本组合已支持。Valve 的当前文档使用 `PROTON_DISABLE_NVAPI` 描述禁用行为，发布页的旧式设置应针对具体版本核对。[Valve Proton 配置说明](https://github.com/ValveSoftware/Proton#runtime-config-options)

## P2：发行检查没有覆盖全部验收门槛

v0.1.0 对应提交的 Release binaries 成功，但同提交 CI 失败。失败来自 Windows 下独立复现脚本使用默认 cp1252 读取 UTF-8 INI；下一提交 `febc5a5` 修复脚本后 CI 全绿。该差异不证明程序二进制存在编码缺陷，但说明发布流程没有等待完整 CI，也没有执行独立复现脚本。

建议：发布任务依赖完整测试及安全回归；对最终打包后的程序执行临时目录的安装、诊断、卸载流程，不能只测 `--version`。构建工具当前未固定版本；后续固定构建依赖并记录环境和来源，便于追溯。

## 面向欧美玩家的发布体验建议

- 当前 Release 标志 `isPrerelease=false`，与 README 的 Developer preview 定位不一致。建议标为 Pre-release，分别显示 Windows CLI / Linux CLI (Experimental)。
- Release 说明目前以中文为主；应英文优先，并给出 Windows PowerShell 的 `./dlss-combo.exe --help` 示例。
- EXE 是命令行程序，不能宣传为“一键图形安装器”。无参数运行会报缺少子命令；双击时可能只看到短暂窗口。后续再考虑向导或启动菜单。
- 两个 ZIP 都仅有可执行文件。建议随包加入英文 Quick Start、版本/源码提交信息和项目许可文件，方便离线查看说明。
- Windows EXE 未签名；应说明实际签名状态，不能把所有安全软件告警都笼统判断为误报，也不应指导玩家关闭保护。
- 主推 Windows 开发预览下载；Linux 明确标实验性和 glibc 下限，先拿到真实 Proton 日志再扩大宣传。

## 验收建议

先修复 INI 覆盖变体，再发布新版本。公开内容保留“免装 Python”的真实优势，同时准确区分命令行工具、图形界面和游戏内效果。当前产物可以视为成功的打包里程碑，但稳定发行验收暂不通过。
